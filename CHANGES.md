# Изменения относительно d0mhate/-tg-ws-proxy-Manager-go v1.4.1

Основа: Flowseal/tg-ws-proxy (MIT, (c) 2026 Flowseal). Лицензия сохранена.

## Исправлено / добавлено

- **TLS к Cloudflare без `X25519MLKEM768`** (аналог правки Flowseal v1.11.3). В Go 1.24+
  гибридный пост-квантовый key share включён по умолчанию, ClientHello становится слишком
  большим, и часть DPI его роняет (таймауты подключения). Теперь предлагаются только
  `X25519`, `P-256`, `P-384`. Больше не нужен `GODEBUG=tlsmlkem=0`.
- **`--cf-prefix`** - метка поддомена перед номером DC для Cloudflare-хостов
  (`<prefix><dc>.<domain>`, по умолчанию `kws`). Часть провайдеров режет TLS по SNI-маске
  `kws*`; с `--cf-prefix cdn` достаточно завести записи `cdn1..cdn5`, `cdn203`.
- **Пул WebSocket для маршрута через Cloudflare.** Раньше каждое новое Telegram-соединение
  открывало TCP + TLS + WebSocket заново (около трёх RTT до Cloudflare), пул работал
  только для прямых хостов Telegram. Теперь свободные подключения к `<prefix><dc>.<domain>`
  держатся наготове и выдаются сразу.
- **Backoff пополнения пула** (upstream `REFILL_BACKOFF_*`): если пополнение не дало ни одного
  подключения, следующее откладывается 1s, 2s, 4s ... (потолок 5 минут, у оригинала час).
  Раньше каждый `Get()` долбил недоступную цель заново.
- **Ротация пула** (upstream `_rotate`): таймер на каждое ведро убирает просроченные и
  мёртвые подключения и заранее докладывает новые, чтобы запрос не платил за рукопожатие
  из-за того, что партия состарилась. Таймеры, а не горутины; ведро, которым не пользуются
  10 минут, перестаёт поддерживаться. Пополнение при `--pool-refill-delay 0` идёт параллельно.
- **Fronting** (upstream `try_fronting_first`): для прямых подключений к IP датацентров
  Telegram, если обычное не удалось, пробуется то же с SNI `--fronting-sni`
  (по умолчанию `sprinthost.ru`, пусто = выключено); удачный режим запоминается.
  Для хостов Cloudflare не применяется.
- Пул и CF-маршрут работают и в режиме `--mode mtproto`.
- **Backoff TCP-fallback** (upstream `TCP_BACKOFF_*`): цель, к которой прямой TCP не
  подключился, не дёргается 30 с, дальше x2 до часа; одновременно только один дайл на цель.
  Отмена клиентом не считается ошибкой цели.
- **Ротация логов**: `--log-file`, `--log-max-mb` (по умолчанию 5), `--log-backups` (минимум 1).
- **`--no-secure`** (upstream `disable_secure`): подключение к хостам Cloudflare по порту 80
  без TLS (режим SSL «Flexible»). SNI не отправляется вообще, поэтому SNI-фильтры не
  срабатывают, и нет затрат на TLS-рукопожатие. К IP Telegram не относится. По умолчанию выключено.
- **CF Worker** (`--cf-worker-domain a.workers.dev,b.workers.dev`): запасной маршрут, когда ни
  Cloudflare по своему домену, ни прямой WebSocket Telegram не сработали. Клиент открывает
  `wss://<worker>/apiws?dst=<IP DC>&dc=<N>`; сам Worker - скрипт из upstream `docs/EN/CfWorker.md`.
  Порядок воркеров случайный. Только режим SOCKS5; без пула. Проверено юнит-тестами, живого
  Worker для проверки у меня не было.
- **Fake TLS (режим `--mode mtproto`, секрет `ee…`), upstream #1473:** серверный ответ теперь
  TLS 1.3-подобный и зеркалит клиента: эхо session id, шифронабор из ClientHello (`0x1301`,
  `0x1303`, `0x1302` по предпочтению), группа key share (`X25519MLKEM768`, если клиент её
  предложил, иначе `X25519` с настоящим публичным ключом). Размер единственной
  ApplicationData-записи берётся с сайта-маски (при старте измеряется первая зашифрованная
  запись `домен:443`, без завершения рукопожатия), при неудаче случайно 64-160 байт вместо
  фиксированных 32. Подпись HMAC по всему потоку сохранена. Старые `AcceptClientHello` и
  `SendFakeServerHello` оставлены для совместимости.

## Не перенесено сознательно

- HTTP/2-мультиплексирование медиа через Cloudflare (upstream `cf_h2.py`, v1.11.0): около
  1300 строк эмпирической логики повторов/опроса поверх MTProto-over-HTTP, которую нельзя
  безопасно проверить без живого Telegram.
- Тестовые DC (10001+, `--force-test-dc`): затрагивает разбор init и маршрутизацию; проверить
  нечем без тестового окружения Telegram.
- GUI/трей, Docker, macOS, Windows 7, i18n, `certifi`, обходы особенностей asyncio и
  `cryptography`: относятся к Python-версии.
- **`--cf-labels`** (`1=lumen,2=orbit,203=zephyr`): своё имя хоста Cloudflare для каждого DC.
  Провайдер блокирует имена по шаблону «слово + номер DC» (сначала `kws<N>`, потом `cdn<N>`),
  поэтому имена можно выбрать произвольно; для DC без записи в списке действует `--cf-prefix`.

## Тесты

Для каждого изменения добавлены тесты; маршрутные тесты Cloudflare выставляют
`PoolSize = 0`, чтобы не запускать фоновое наполнение пула.
